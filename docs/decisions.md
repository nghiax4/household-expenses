# Decisions Log

Key decisions and why they were made. Newest first.

| Date | Decision | Reason |
|------|----------|--------|
| 2026-11-22 | **Every wait shows a spinner and a seconds counter from 0s; the app gives up after 60 s** (for saves: "it may still have saved, check the list"). Uses a plain timer + `AbortController`, not `AbortSignal.timeout`. | User's request: waits gave no sign of life, and nothing stopped a hung request. A true progress bar is impossible (one answer, no progress), so the counter is the honest moving part. (It first appeared only after 3 s; the user asked for it from 0s.) The plain timer works on iPhones older than iOS 16, and tests can fast-forward it. |
| 2026-11-22 | **Shares are marked from a "Mark who paid" checklist with one Save**, not by tapping chips; the request carries only the changed shares with their new statuses, applied all-or-nothing. On screen the payer's row says "Paid the bill" and others "Paid back". | User's choice after trying tappable chips (it wasn't clear they could be tapped) and comparing six designs. A button says what it does, Save is the confirmation, and several people can be marked at once. Sending statuses rather than "toggle" makes a repeat or stale request harmless. |
| 2026-11-22 | **A payer outside the split stays allowed** (they're owed the full total), with a hint on the Add form when it happens. | User confirmed after trying it: paying only for others is real, and the hint catches a missed tap. |
| 2026-11-21 | **Add form has no default payer or participants**; the user picks both every time (a live preview shows each share). | A wrong default (e.g., "everyone") would be saved silently and skew balances. Claude's call while the user deferred; easy to change after trying it on the phone (e.g., remember the last payer per phone). |
| 2026-11-21 | **Backend reads displayed cell text** (`getDisplayValues`) and writes Date/Total with number formats and other text as literal text. Each request takes a script-wide lock. `addExpense` returns the whole Expenses tab read back. | Parsing what a person sees in the sheet uses the same strict rules as the person cells and matches the guiding principle. Literal text keeps descriptions exactly as typed. One lock for all requests is the simplest way to make IDs safe. Reading back proves the write round-trips. |
| 2026-11-21 | **Unreadable Expenses rows are hidden from the app and listed in a banner** (row number + reason) instead of failing the whole load. A broken header still fails the load. | One bad hand edit shouldn't lock everyone out, and guessing would risk wrong money. A broken header means the column meaning is unknown, so nothing can be trusted. |
| 2026-11-21 | `Expense.people` is a plain object keyed by name (was a `Map`), so expenses travel as JSON unchanged. Column order always comes from the `people` list. | One representation from sheet to screen instead of converting at the boundary. |
| 2026-11-20 | **No display name and no "who"**: every phone gets the same UI. Activity records what changed and when (Time, Action, Details); Ideas records when (no Who column). The "what I owe" view picks a person from a list on that screen. | User's choice ("everyone should get the same UI"), made knowing the log can't say who made a change. It still shows the before → after values, so mistakes stay visible and fixable. |
| 2026-11-20 | **Typing uses the iPhone keyboard** (text boxes; Vietnamese from the phone's own Vietnamese keyboard). Dates: Today / Yesterday buttons plus the iPhone's date picker. Numbers: the iPhone's number keypad (digit keypad for the passcode, decimal keypad for amounts); the app's own number pad was removed. Supersedes the custom letter keyboard with Telex decided earlier the same day, which was built, tried on the phone and deleted uncommitted. | The user tried both and preferred the iPhone keyboard; the earlier slowness was likely Safari's page zoom at 50%. The system keyboard gives back paste, autocorrect and dictation and is much less code. The date picker saves building a calendar. For numbers the user picked the iPhone keypad too, knowing it has no Done key and amounts get checked on save instead of while typing. |
| 2026-11-20 | (Superseded the same day by the row above.) **No iOS keyboard or date picker anywhere**: an in-app number pad, a letter keyboard with Telex, Today/Yesterday + an in-app calendar, and recent-description chips. | User's request at the time: the iOS keyboard felt slow on the household's iPhones. |
| 2026-11-19 | **Backend wiring**: one Apps Script web app (runs as the owner, open to anyone; the passcode is the gate). The app POSTs JSON as `text/plain` and gets `{ok, value}` / `{ok, error}` back; request types live in `src/api/protocol.ts`, shared by both sides. Settings live in Script Properties (`PASSCODE`, `PEOPLE`, `SPREADSHEET_ID`), never in code. A one-time `setupStorage` creates the storage sheet. Redeploys reuse one deployment, so the URL never changes. | `text/plain` avoids the CORS preflight Apps Script can't answer (tested live from a browser). Script Properties keep secrets and real names out of the public repo. The only permission requested is Google Sheets. |
| 2026-11-19 | **Household passcode: a 4-digit code**, stored only in the script's private settings (value in private notes). No lockout after wrong guesses. | User's choice, made knowing a script could try all 10,000 codes in about an hour: "safer than no passcode, worse than a phrase, and good enough". Can be changed any time in Script Properties. |
| 2026-11-19 | **Public repo** `nghiax4/household-expenses`, hosted free on **GitHub Pages**. Friends' names, real amounts and Drive links stay out of the repo, in git-ignored `docs/private-notes.md`; tests use made-up data. History was squashed into one clean commit before the first push. The commit email stays (the user's GitHub is public on purpose). | A public repo is searchable and permanent, and it sits on the profile the user shows recruiters. The friends agreed to a link-shared sheet, not to that. Keeping real data out costs nothing: the app reads people from the private sheet. |
| 2026-11-19 | **Folder layout**: one npm package at the repo root. `src/domain/` (pure money logic, no I/O, unit-tested next to each file), `src/ui/` (React screens), `e2e/` (Playwright), and, with the backend step, `src/api/` (talks to the backend) and `apps-script/` (the backend itself). | Every file has an obvious home, and domain logic stays separate from I/O and UI, as CLAUDE.md requires. |
| 2026-11-19 | **Backend in TypeScript**, in `apps-script/`, bundled into one file and uploaded with Google's `clasp` tool. It imports `src/domain` to read and check sheet cells. | The backend and the app must parse `"$12.34 · Paid"` with identical rules. One shared copy means they can't drift apart. Costs a small build step. (Claude's call; the user deferred.) |
| 2026-11-19 | **iPhone-first**: the phone e2e tests and phone screenshots use Playwright's **WebKit** (Safari's engine) as an iPhone 15 (393px). Claude in Chrome is used for desktop checks only. | Everyone in the household uses an iPhone, and every iPhone browser (Chrome included) runs on WebKit. Chrome's window couldn't get to iPhone width here, and Playwright screenshots are exact. |
| 2026-11-19 | Tooling: **npm**; Vite builds with `base: './'`; Playwright runs every e2e test in desktop Chrome and on the iPhone 15 (WebKit); TypeScript `strict` plus `noUncheckedIndexedAccess`. | npm is the default. A relative base works under any GitHub Pages repo name. The strict index checks catch off-by-one mistakes in money code. |
| 2026-11-19 | Percentages are entered as **basis points** (hundredths of a percent, 12.5% = 1250) and rounded like an equal split: each share rounds down, and the leftover cents go to the payer (or in column order). Every share must be more than $0.00; a $0.00 share is "Not involved" instead. | Integers keep the math exact. One rounding rule everywhere is easier to explain. A $0.00 share would be a second way to say "not involved". |
| 2026-11-19 | **Ideas inbox (MVP)**: a 5th storage tab, Ideas (ID, Created at, Note, Status Open/Done/Dropped, Outcome; the Who column was dropped 2026-11-20), plus a simple app screen. Not written to Activity. | User's request: jot down ideas about the app on the phone, then discuss them with Claude Code later, which keeps the app easy to change. | 2026-11-19 | **Claude reads the Ideas tab at session start through the Google Drive connector** (read-only). | 2026-11-17 | **Non-participants are stored and shown as "Not involved"** (gray text), never blank. Adding a person fills their column with "Not involved" on old rows.
